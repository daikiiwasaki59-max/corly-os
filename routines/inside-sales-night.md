# 夜のインサイドセールス（inside-sales）— 毎日 22:30 JST

役職: `.claude/agents/inside-sales.md`。共通前提: `routines/_common.md`。

## 目的
岩崎が寝ている間に、①承認済みを送る ②返信を拾う ③翌朝の承認待ちを用意する。

## 手順
1. `routines/_common.md` §0 でリポジトリを最新にする。
2. **岩崎の返信を読む**: Gmail `search_threads` で `from:daikiiwasaki59@gmail.com subject:朝の1通 newer_than:2d`、各スレッドを `get_thread` で全文取得。岩崎の返信本文から次を読み取る。
   - `承認 A0001 A0003` → `data/approvals.csv` の該当行を 状態＝承認
   - `修正 A0002 <指示>` → 状態＝修正、岩崎メモ＝指示。下書きを直して新しい依頼IDで承認待ちに戻す
   - `却下 A0004` → 状態＝却下
   - `所在地: … / 電話: … / メール: …` → `company/00_contact.md` の表に転記し登録日を入れる
   - 読み取れない行は無視し、`data/log.csv` に「解釈不能」と残す
3. **送る**: 状態＝承認 かつ 処理日時が空 の行を、上から最大5件。
   - `company/00_contact.md` が未登録なら送らず、log に「フッター未登録のため送信見送り」。
   - 下書き本文（下書きの場所 に書かれたファイル or 本文）＋フッターで Gmail `send_message`。
   - 送ったら: 処理日時を記入、取引先CSVの ステージ＝初回接触、最終接触日＝今日、次アクション＝「返信待ち」、期限＝7日後。
4. **返信を拾う**: Gmail `newer_than:1d -from:daikiiwasaki59@gmail.com -in:draft` を取り、差出人ドメインが取引先CSVの URL ドメインと一致するものを「返信あり」に。
   - 取引先CSV: ステージ＝返信あり、最終接触日＝今日
   - 要約（相手 / 要旨 / 温度感 高中低 / 提案する次アクション）を作り、返信の下書きを `data/drafts/<取引先ID>_<日付>.txt` に保存
   - `data/approvals.csv` に 行為＝返信メール送信 として承認待ちを1行追加
5. **翌朝の承認待ちを用意する**（フッター登録済みのときだけ。未登録なら「フッター待ち」として下書きだけ作る）:
   - 取引先CSVで 事業＝清掃、優先度＝高、ステージ＝未接触、**メール列が入っている**、連絡NG≠TRUE の先を上から最大3件
   - `company/04_templates.md` §1 の型で初回メールを起こし、`data/drafts/<取引先ID>_<日付>.txt` に保存。**価格・実績の数字は入れない。** 相手固有の1行は取引先CSVのメモ・URLから分かる範囲で。分からなければ「{相手固有の1行}」のまま残し、承認待ちの内容欄に「要加筆」と書く
   - `data/approvals.csv` に 行為＝初回メール送信 として1行追加（依頼ID は A + 4桁連番）
   - メール列が空の先しか無ければ、log に「メールアドレス未登録のため下書き0件」と残し、朝の1通の「栓」に上がるようにする
6. **燃料**: 事業＝燃料 は、`company/INPUT_REQUIRED.md` に「配送業者の既存顧客の確認方法」が登録されるまで **触らない**。log に1行残すだけ。
7. `data/log.csv` に1行（送信 n / 返信 n / 下書き n）を追記し、commit / push。

## やらない
- 承認なしの送信。フッター無しの送信。価格表にない金額。一斉送信。
- WebFetch で会社サイトを開きに行かない（この環境では遮断される。時間の無駄）。
