# 夜のインサイドセールス（inside-sales）— 毎日 22:30 JST

役職: `.claude/agents/inside-sales.md`（一言メモの活動ログ化は `outside-sales.md` の担当分も兼ねる）。共通前提: `routines/_common.md`。

## 目的
岩崎が寝ている間に、①今日の電話・訪問の結果を正データに落とす ②承認済みだけ送る ③返信・折返しを拾う ④明日のコールリストと訪問の材料を作る。
順番は「岩崎の入力を全部読む → 書く → 送る → 明日を作る」。送る前にメモを読むのは、今夜のメモに NG があれば承認済みでも送らないため。

## 手順
1. `routines/_common.md` §0 でリポジトリを最新にする。Drive「CORLY OS/部隊バックアップ」に未適用があれば先に取り込む。

2. **岩崎の返信を全行読む**
   - Gmail `search_threads`: `from:daikiiwasaki59@gmail.com subject:朝の1通 newer_than:2d` → 各スレッド `get_thread`。岩崎の返信本文を行に分解。引用行（`>`）・署名・空行は捨てる。既に活動CSVの「元メモ」に同じ原文＋同じメモ受信日時があれば処理済みとして飛ばす。
   - 行頭の1語で振り分け:
     - `承認 A….` → approvals.csv 状態=承認／`修正 A…. <指示>` → 状態=修正、岩崎メモ=指示、下書きを直して新IDで状態=待ち／`却下 A….` → 状態=却下。同じIDに矛盾があれば後の行を採用し log に残す。存在しないID・IDなしは解釈不能。
     - `所在地:` `電話:` `メール:` → `company/00_contact.md` に転記し登録日を入れる。
     - `日報 …` → `data/daily.csv` に1行（記録者=岩崎）。
     - `C0…` または取引先CSVの会社名に一意に当たる語 → 一言メモ（次項）。2社以上に当たる／当たらない → 解釈不能。
     - `C0… NG解除 <理由>` → 連絡NG=FALSE、NG理由に「解除 日付 理由」。岩崎の行だけで解除する。
     - `C0… 訂正 …` → 同じ取引先の当日の活動行を 解釈状態=訂正済 にし、新しい行で上書き。
     - それ以外 → 解釈不能。活動CSVに 解釈状態=不能、元メモ=原文 で残す。**推測で埋めない。**
   - 一言メモの書式: `<取引先ID> <結果> [担当:<名前> [<役職>]] [次:<日付> [<時刻>] <行為>] [NG] [<失注理由>] [メモ:<自由文>]`
     | 結果 | 活動CSV | 取引先CSVの更新 |
     |---|---|---|
     | 話した | チャネル=電話 | ステージ 未接触→初回接触、最終接触日=今日、最終通話日=今日、最終通話結果=話した、コール回数+1 |
     | 留守 | 同 | 最終通話日=今日、最終通話結果=留守、コール回数+1、次回架電可日=2営業日後（仮置き）。コール回数≥3 なら 次アクション=郵送または低優先、期限=空 |
     | 折返し | 同 | 次アクション=折返し待ち、期限=`次:` or 翌営業日、最終通話日=今日、コール回数+1 |
     | 受付 | 同 | 受付突破メモ=`メモ:` の内容、最終通話日=今日、コール回数+1 |
     | 資料 | 同 | 話した と同じ ＋ `メール:` があればメール列。フォロー下書き対象 |
     | アポ | 同 | 話した と同じ ＋ 次アクション=訪問、期限=`次:` の日付。Calendar `create_event`「訪問 会社名（取引先ID）」（岩崎本人の予定のみ。顧客は招待しない） |
     | 訪問済 | チャネル=訪問 | 最終接触日=今日。`メモ:` に 見積/提案 があれば ステージ=提案済。次アクション/期限は `次:` から |
     | 断り | 通話 or 訪問 | ステージ=失注、失注理由=行内の 価格/時期/既存契約/不要/不明（無ければ 不明）。時期なら 次アクション=再接触、期限=6か月後（仮置き）。**連絡NG は立てない** |
     | NG | 同 | 連絡NG=TRUE、NG理由=「岩崎指示 日付」 |
     | 番号違い | 同 | 電話確度=低、電話メモ=「不通 日付」、電話検索日=空（再検索対象に戻す） |
     - `次:` の日付は今日以降で最も近い年。`明日` `来週`（翌週月曜、仮置き）`n日後` `月末` を受ける。
     - 解釈できなかった語句は捨てず活動CSVのメモへ。個人携帯・個人メールは取引先CSVに入れず活動メモに留める。
     - 活動CSVの列: 活動ID（`ACT000001`）、日時（メモ受信日時）、取引先ID、案件ID、チャネル、結果、担当者、メモ、次アクション、期限、記録者=岩崎、元メモ、メモ受信日時、解釈状態、通話n回目。

3. **送る**（approvals.csv 状態=承認 かつ 処理日時が空。上から最大5通、仮置き）
   - 送信前チェック。1つでも落ちたら送らず 状態=保留、岩崎メモに理由: ①宛先が 連絡NG≠TRUE（今夜 NG になった先を含む）②`00_contact.md` 登録済み ③1通目は数字ゼロ、2通目以降は `01_products.md` の登録値のみ ④フッターあり ⑤宛先メール＝取引先CSVのメール列。
   - 送信直前に岩崎メモへ「送信中 時刻」を書いて commit → `send_message` → 処理日時を書いて commit。起動時に「送信中」のまま処理日時が空の行があれば送らず栓へ（`in:sent to:<宛先>` で確認して岩崎に判断を仰ぐ）。
   - 送ったら活動CSVに1行（チャネル=メール、結果=送信済、記録者=AI）、取引先CSV 最終接触日=今日、次アクション=返信待ち、期限=7日後。
   - 失敗: 状態=承認のまま、岩崎メモに「送信失敗 日付 エラー」。翌晩再試行。3回で 状態=保留。

4. **返信を拾う**（Gmail `newer_than:1d -from:daikiiwasaki59@gmail.com -in:draft`。差出人ドメイン＝取引先CSVの URL ドメイン、または差出人＝メール列）
   - 「配信停止」「送らないで」「不要です」「今後のご連絡は」を含む → 連絡NG=TRUE、NG理由=「受信拒否 日付」。返信も承認待ちも作らない。log に「NG化」。
   - それ以外 → 取引先CSV ステージ=返信あり、最終接触日=今日。要約（相手/要旨/温度感 高中低/次アクション）と返信下書きを `data/drafts/<取引先ID>_<日付>.txt`、approvals.csv に 行為=返信メール送信 で1行。本文に電話番号があれば電話列へ（確度=高、出所=返信メール）。

5. **通話後フォローの下書き**（今夜のメモで結果が 話した/資料/アポ/訪問済 の先。1社1通）
   - 型: 件名「本日はお電話（ご訪問）ありがとうございました（庄栄興産 岩崎）」／宛名／お礼1文／**メモから1行**（「立会を社長が出られていると伺いました」）／結果別の1文（資料→概要を送る旨、アポ→日時の確認、話した・訪問済→「次の退去1件、立会だけでもお預かりできます」）／フッター。価格・実績の数字ゼロ。
   - `data/drafts/<取引先ID>_<日付>.txt` に保存、approvals.csv に 行為=フォローメール送信。宛先メールが空なら内容欄に「宛先メール未登録（返信で `C0… メール:…` を）」、`00_contact.md` 未登録なら「フッター待ち」。
   - 燃料の先は `INPUT_REQUIRED.md` §3 の「顧客に言ってよい内容」が未登録の間は下書きを作らず log に1行。

6. **明日のコールリストを作る** → `data/calllists/YYYY-MM-DD.csv`（翌営業日。土日祝は作らない: 仮置き）
   - 列: 順位、取引先ID、会社名、市区町村、電話、電話確度、前回日、前回結果、コール回数、担当者名、受付突破メモ、固有の1行、想定反論、選定理由。
   - 母集合: 事業=清掃、連絡NG≠TRUE、電話あり、ステージ∉{成約,失注}、最終通話日≠今日、次回架電可日≤明日。**燃料は `INPUT_REQUIRED.md` §0-4（尼崎の新ターゲットの条件）と §3「配送業者の既存顧客の確認方法」が登録されるまで入れない**（log に「燃料 n社 方針待ち」）。登録後は `docs/research/fuel-minilorry-amagasaki.csv` の「ターゲット候補」を優先し、42社のエンド顧客リストは後ろに回す。
   - 段の順に詰めて10社で打ち切り: ①折返し待ち／再架電 で期限≤明日 ②次アクション期限≤明日（訪問以外）③前回=留守 かつ 2営業日以上経過 かつ コール回数<3（備考「午後推奨」）④未接触×優先度高×確度高 ⑤未接触×優先度高×確度中 ⑥未接触×優先度中×確度高。
   - 同じ段の中: 明日の訪問先（Calendar 明日）の市区町村と同じ → 隣接 → その他。訪問がなければ 豊中 → 吹田・箕面・池田・伊丹 → 大阪市北部。同市内は取込日が古い順。
   - 固有の1行: 取引先CSVのメモ・URL・活動CSVから分かる事実だけ（管理戸数、エリア、前回の担当者の一言）。無ければ「なし」。**推測で書かない。**
   - 想定反論: 活動メモ・取引先メモに根拠があるものだけ（「前回『業者は足りている』」→ 返し）。無ければ「共通のみ」。返しは `03_playbook.md` A-2/A-4/A-7、C-3 から。
   - 10社に満たなければ理由を log と朝の栓に（候補が尽きた／架電可日未到達）。水増ししない。

7. **電話番号の補完**（WebSearch。1晩10社まで。WebFetch はしない）
   - 対象: 事業=清掃、優先度 高→中、電話列が空、連絡NG≠TRUE、電話検索日が空または30日以上前。
   - `"<会社名>" <市区町村> 電話` で検索。スニペットに `0X-XXXX-XXXX` 形式の番号があり、同じスニペットに会社名または URL ドメインが含まれるときだけ採用 → 電話、電話確度=中、電話出所=結果URL、電話検索日=今日。
   - 番号が2つ以上／会社名の一致が取れない → 採用せず 電話メモに候補、確度=低、電話検索日=今日。見つからなければ電話検索日だけ更新。
   - フリーダイヤルより市外局番を優先。個人名・個人携帯は取らない。

8. **日報**（岩崎の `日報` 行が無ければ）活動CSVの今日分から 訪問/架電/話せた/アポ/送信 を数えて `data/daily.csv` に1行（記録者=AI）。

9. `data/log.csv` に1行: `メモ取込 n（不能 n）/活動追記 n/送信 n/返信 n/NG化 n/フォロー下書き n/コールリスト n社/電話補完 n`。commit / push。
   - push 失敗: `git pull --rebase` → push を3回。だめなら変更した CSV を Google Drive「CORLY OS/部隊バックアップ/YYYY-MM-DD/」に `create_file` し、log 相当を朝の栓に載せるため `data/` の代わりに Drive の同フォルダへ `log-YYYY-MM-DD.txt` を置く。

## やらない
- 承認なしの送信。フッター無しの送信。価格表にない金額。一斉送信。同文の使い回し。
- 連絡NG の解除（岩崎の行だけ）。断りを NG に格上げしない。
- 岩崎のメモにない事実を補わない。解釈できない行を推測で埋めない（栓に上げる）。
- 同じ会社を同じ日に2回コールリストに入れない。前日のリストと同じ先を、最終通話日が入っていないという理由だけで外さない（岩崎がメモを書かなかった可能性がある。朝の栓で聞く）。
- WebFetch で会社サイトを開かない（遮断）。WebSearch は電話補完の10社まで。
