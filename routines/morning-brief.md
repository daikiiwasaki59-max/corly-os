# 朝の1通（admin）— 毎日 6:30 JST

役職: `.claude/agents/admin.md`。共通前提: `routines/_common.md`。

## 目的
岩崎がこの1通だけ持って外に出れば、今日の電話10件と訪問ができる。返信が承認と活動記録になる。
朝は「夜が用意したものを1通に整形する」だけ。判断・並べ替え・調査はしない（6:30 に確実に届くことを優先）。

## 手順
1. `routines/_common.md` §0 でリポジトリを最新にする。Drive「CORLY OS/部隊バックアップ」に未適用フォルダがあれば取り込む（§0-2）。
2. 読む（探さない。無ければ「なし」または「未作成」）
   - `data/calllists/YYYY-MM-DD.csv`（今日の日付）: 今日かける先
   - Google Calendar `list_events` 今日: 予定。タイトル/説明に取引先ID or 取引先CSVの会社名を含むものは「訪問パック」へ
   - 取引先CSV（`docs/research/pm-list-osaka-master.csv` `fuel-prospects-osaka-hanshin.csv`）: 次アクション=訪問 かつ 期限=今日 → 訪問パックへ／それ以外で 期限 ≤ 今日 → 「期限」へ
   - `data/approvals.csv`: 状態=待ち、状態=保留
   - `data/activities.csv`: 昨日以降で 解釈状態=不能 の行（原文を栓へ）
   - `data/log.csv`: 昨夜の inside-sales の行（数字はここから写す。再集計しない）
   - `company/00_contact.md`: 所在地・電話・メールが登録済みか
   - `company/03_playbook.md` A-2/A-4/A-5/A-7、C-3: 共通トーク・聞く4項目・共通の反論。C-3（採用済みの返し）があれば共通の反論の先頭に置く
3. 書く（Gmail `send_message`、宛先 daikiiwasaki59@gmail.com、プレーンテキスト）
   - 件名: `【朝の1通】YYYY-MM-DD`
   - 本文の型（この順。該当なしは1行「なし」）:
     ```
     今日かける先 N社（管理会社 n / 燃料 n）
     共通トーク（30秒）: 04_templates.md §3 の本文
     聞く4項目: ①月の退去件数 ②立会は誰 ③工事・清掃は何社 ④一番の手間
     出口: 「次の退去1件、立会だけ試しに」
     共通の反論と返し: 03_playbook.md から3つまで
      1. 取引先ID 会社名（市区町村） 電話 [確度:高/中]
         前回: 日付 結果（n回目）／担当: 名前 or 未登録／受付: 受付突破メモ or 未登録
         固有の1行: コールリストの「固有の1行」
         想定反論: コールリストの「想定反論」or「共通のみ」
      2. …（コールリストの順のまま。1社4行以内）
     今日の訪問パック N件
      時刻 取引先ID 会社名（市区町村） 決裁者: 役職 氏名 or 未登録
         前回: 直近の活動CSV1行（日付 チャネル 結果 担当者 メモ要約）
         今回の狙い: 次アクション列の内容。無ければ「4項目を聞き切る → 立会お試し」
         想定反論: 取引先メモ・活動メモに根拠があるものだけ。価格は「価格表①の登録値のみ。立会代行は未登録→後日お見積り」
     承認待ち N件
       A0007 [役職/行為] 宛先名 — 内容の要約（1行）。保留は「保留（理由）」を付ける
     期限（今日まで）
       取引先ID 会社名 次アクション 期限 → 今日のかける先に入っていれば「n位に入れ済み」
     今日の予定
       時刻 タイトル（取引先に紐づかないものも全部）
     昨夜の部隊
       log.csv の1行をそのまま（メモ取込 n（不能 n）/活動追記 n/送信 n/返信 n/NG化 n/フォロー下書き n/コールリスト n社/電話補完 n）
     栓になっていること
       ・00_contact.md 未登録 → 「返信で 所在地: / 電話: / メール: の3行」
       ・コールリスト未作成 → 前日のリストから 最終通話日≠昨日 の先を再掲した旨
       ・解釈不能行 → 原文と「書き直し方」
       ・送信失敗・保留・push失敗
       ・燃料 方針待ち（INPUT_REQUIRED §3 が未登録の間、毎日1行）
     返信の書き方（このメールに返信。1行1件）
       承認 A0007 A0008 ／ 修正 A0007 <指示> ／ 却下 A0008
       C000016 話した 担当:山本 次:10/3 訪問 14:00
       C000031 留守 ／ C000019 断り 既存契約 ／ C000020 NG ／ C000016 受付 メモ:工事課は午後
       日報 訪問2 電話9 話せた3 アポ1
       所在地: … / 電話: … / メール: …
     ```
   - 数字は実績値のみ（取引先CSV・活動CSV・log.csv に書いてあるものだけ）。価格は書かない。
   - コールリストが未作成のとき: 前日の `data/calllists/` を読み、取引先CSVの 最終通話日≠昨日 の先だけ同じ順で載せる。並べ替え・追加はしない。
4. `data/log.csv` に1行追記し、commit / push。

## やらない
- 顧客へ送らない。承認待ちを承認しない。会社知識を書き換えない。
- コールリストを作らない・並べ替えない（夜の仕事）。WebSearch もしない。
- 取引先CSVに書かない（最終通話日などは夜がメモから書く）。
