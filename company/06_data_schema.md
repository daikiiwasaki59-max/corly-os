# 06 データ定義と正データの場所

## 正データ
| 種類 | 場所 | 区分 |
|---|---|---|
| 取引先・案件・活動・見積・承認待ち・日報・価格表 | Google スプレッドシート「CORLY OS」1冊 | 岩崎回答（2026-09-11） |
| 会計・請求書 | freee（会計・請求書）。他サービスで代替可 | 岩崎回答 |
| 会社知識 | このリポジトリ `company/` | — |

雛形は `apps-script/setup-sheets.gs` の `setupCorlySheets()` を1回実行して作る（`docs/setup-phase0.md`）。

## 設計判断
- **新規リストと見込みリストは別シートにせず、「取引先」1枚でステージで区別する。** 未接触＝新規リスト、初回接触以降＝見込み。燃料の数百〜数千件も「事業」列で区別して同じシートに入れる。フィルタ表示で「事業＝燃料 かつ ステージ＝未接触」を新規リストとして見る。
- 1人運用なので、シートを増やすより列を増やす。

## シート定義
### 取引先
| 列 | 内容 |
|---|---|
| 取引先ID | `C000001` 形式 |
| 事業 | 清掃 / 燃料 / 両方 |
| 会社名 | |
| 業種 | `02_icp.md` の区分 |
| 都道府県 / 市区町村 / 住所 | |
| 決裁者役職 / 決裁者氏名 | 氏名は個人情報。必要な先のみ |
| 電話 / メール / LINE / Instagram / X / URL | |
| 紹介元 | 取引先ID |
| ステージ | 未接触 / 初回接触 / 提案済 / 交渉中 / 成約 / 失注 |
| 優先度 | 高 / 中 / 低 |
| 連絡NG | TRUE なら再送禁止 |

| リスト出所 | 自作 / 購入 / LIOAS提供 / 紹介 / Web |
| 取込日 / 最終接触日 / 次アクション / 次アクション期限 | |
| メモ | |
| 重複キー | 会社名＋電話の正規化文字列 |

### 案件
案件ID（`D000001`）、取引先ID、商材（清掃 / 燃料）、ステージ、月額、単発金額、確度（高 / 中 / 低）、次アクション、期限、失注理由（価格 / 時期 / 既存契約 / 不要 / 不明）、成約日、開始日、LIOAS送客日、LIOAS契約状況。

### 活動
活動ID（`A000001`）、日時、取引先ID、案件ID、チャネル、結果、メモ、次アクション、期限、記録者（岩崎 / AI）。

### 見積
見積ID、案件ID、明細（JSON 文字列）、小計、消費税、合計、有効期限、発行状態（下書き / 承認 / 送付）、ファイルURL。

### 請求
請求ID、案件ID、freee請求書ID、金額、発行日、支払期日、入金日、状態（下書き / 発行 / 入金済 / 督促中）。

### 価格表
商材コード、商材名、単価、単位、原価、条件、区分（実績値 / 仮置き）、更新日。
**AIはこのシートまたは `01_products.md` からしか価格を引かない。**

### 承認待ち
依頼日時、役職、行為、宛先、内容、下書きの場所、理由、リスク、状態（待ち / 承認 / 修正 / 却下）、岩崎メモ、処理日時。

### 日報
日付、訪問、架電、メール送信、DM送信、アポ獲得、成約、所感、明日のアクション、記録者。

## 個人情報の扱い
- 法人名・代表電話・代表メールは原則、個人情報に当たらない。担当者氏名・個人携帯・個人メールは個人情報として扱う。
- AIへ渡すのは業務上必要な列のみ。数千件のリストを丸ごとAIに読ませない。「ステージ＝未接触 かつ 優先度＝高」など絞ってから。
- リストの出所が「購入」なら、購入元の利用規約（第三者提供・利用目的）を確認してから使う。最終確認は専門家へ。
