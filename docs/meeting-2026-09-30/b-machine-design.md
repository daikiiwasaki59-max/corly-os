## 結論（先に3行）
1. いまの3本は「AIがメールを下書き → 岩崎が承認 → 夜に送る」が主軸。だが管理会社204社にメールは0件、契約は電話→訪問で決まる。**主軸を「夜に明日のコールリストを作る → 朝に渡す → 岩崎が電話 → 一言メモ → 夜がログ化して次を作る」に組み替える。** メールは「通話後のフォロー」に降格する。
2. 岩崎の入力は **「朝の1通」への返信1本** に集約する。承認も、通話後の一言メモも、会社情報の登録も、同じスレッドに1行ずつ書く。部隊は行頭の1語で解釈する。
3. 電話番号が最大の栓。管理会社の正データ（master 204社）で電話があるのは **20社（実績値）**、別表 `pm-list-north-osaka.csv` 20社中 9社（実績値。master との重複は未照合）。夜の部隊が WebSearch で1晩10社ずつ補う（確度:中）。燃料は42社中30社に電話あり（実績値。会議資料の「42社は電話あり」より少ない）だが「配送業者の既存顧客の確認方法」が未登録なので、方針が決まるまでコールリストに載せない。

## 1. 24時間サイクル（電話→訪問を軸に）

- **日中に部隊は動かない。** 午前の通話結果が午後の訪問パックに反映されない。当面は岩崎がカレンダーに手で入れる。1週間回して「昼に1本欲しい」となったら 12:30 の4本目（承認・メモの取り込みだけの軽い版）を追加する。今は入れない（コスト上限 月1〜2万円・承認負荷）。

## 3. 「通話後の一言メモ」の受け取りと変換

### チャネル
**第一候補: 「【朝の1通】YYYY-MM-DD」への Gmail 返信。** 理由: 承認と同じスレッドなので岩崎が探さない。件名が固定なので部隊の検索が1本で済む（`from:daikiiwasaki59@gmail.com subject:朝の1通 newer_than:2d`）。音声入力→Gmail アプリで返信、で成立する。
- 返信は何通でもよい。1通に1行でも、まとめて10行でもよい。
- 昨日のスレッドに返信しても拾う（newer_than:2d）。日付が違うメモは「メモ受信日時」で判定する。
- 第二候補（将来）: LINE 公式アカウント。段階1で接続後、同じ書式・同じ解釈器を使う。

### メモの書式
```
<取引先ID> <結果> [担当:<名前>] [次:<日付> [<時刻>] <行為>] [NG] [<失注理由>] [メモ:<自由文>]
```
- **取引先ID が先頭**（`C000016`）。ID が分からないときは会社名でもよい（`岸岡 留守`）。部隊は取引先CSVの会社名で前方一致・部分一致し、**候補が1社に絞れないときは解釈不能にして朝に聞く**（推測で当てない）。
- **結果は1語**（下表）。2語目に来る。
- 以降はキーワード付きの任意項目。順不同。区切りは半角/全角スペース。

| 結果の語 | 意味 | 部隊がやること |
|---|---|---|
| `話した` | 決裁者または担当者と会話できた | 活動追記、ステージ 未接触→初回接触、最終接触日=今日、コール回数+1、最終通話結果=話した |
| `留守` | 不在・話中・出ない | 活動追記、コール回数+1、最終通話結果=留守、次回架電可日=2営業日後（仮置き）。コール回数≥3（仮置き）なら 次アクション="郵送または低優先" にして朝の栓ではなく週次に回す |
| `折返し` | 折り返しを頼んだ／もらう約束 | 活動追記、次アクション="折返し待ち"、期限=翌営業日（`次:` があればそれ）。翌日のコールリスト1位 |
| `受付` | 受付で止まった | 活動追記、コール回数+1、`メモ:` の内容を **受付突破メモ** 列に転記（例: 「工事課は午後」） |
| `資料` | 資料送付を頼まれた | 活動追記、**フォローメール下書き**（§4-3）。`メール:` があれば取引先CSVのメール列に入れる |
| `アポ` | 訪問の約束が取れた | 活動追記、次アクション="訪問"、期限=`次:` の日付。カレンダーに「訪問 会社名（取引先ID）」を作る（岩崎本人の予定＝自動OK。**顧客への招待はしない**） |
| `訪問済` | 訪問した | 活動追記（チャネル=訪問）、ステージ 初回接触→提案済（`メモ:` に「見積」「提案」があれば）。日報の材料 |
| `断り` | 断られた | 活動追記、ステージ=失注、失注理由=同じ行の `価格/時期/既存契約/不要/不明` のいずれか（無ければ 不明）。**連絡NG は立てない**（時期の断りは半年後に戻る） |
| `NG` | 二度と連絡するなと言われた／連絡NGにする | 連絡NG=TRUE、NG理由=「岩崎指示 日付」。以後すべてのリストから除外 |
| `番号違い` | 電話が通じない・別会社 | 電話確度=低、電話列は残して `電話メモ` に「不通 日付」。夜の電話補完の対象に戻す |
| `日報` | その日の集計を岩崎が書く | 日報CSVに1行（岩崎記録）。無ければ部隊が活動CSVから集計（AI記録） |

任意項目の解釈:
- `担当:山本` → 担当者名列。役職が続けば `担当:山本 課長` → 担当者名=山本、担当者役職=課長。**個人名は業務上必要な範囲**（`06_data_schema.md`）。携帯番号・個人メールは書かれても取引先CSVには入れず活動CSVのメモに留める。
- `次:10/3 訪問 14:00` → 次アクション=訪問、期限=2026-10-03、時刻があればカレンダー作成に使う。年は「今日以降で最も近い」。`明日` `来週` `3日後` `月末` も受ける。`来週` は翌週月曜（仮置き）。
- `メモ:` 以降は全部自由文として活動CSVのメモへ。キーワードがなくても、解釈できなかった残りの語句は捨てずにメモへ入れる。
- 1行に2つの取引先IDがあれば2行として扱う。
- 同じ取引先に同じ日に複数行あれば、全部を活動CSVに時系列で追記し、取引先CSVは最後の行で更新。

### 変換の流れ（夜の部隊）
1. スレッド取得 → 岩崎の返信本文を行に分解 → 引用行（`>` で始まる）と署名を除去。
2. 行頭の1語で振り分け: `承認/修正/却下` → 承認処理（§4-1）／`所在地:/電話:/メール:` → 会社情報転記／`日報` → 日報／`C0` または会社名 → 一言メモ／それ以外 → 解釈不能。
3. 一言メモ1行 → 活動CSVに1行（活動ID採番、日時=メモ受信日時、チャネル=電話 or 訪問、結果、担当者、メモ、次アクション、期限、記録者=岩崎、**元メモ=原文**、解釈状態=OK）。
4. 取引先CSVを更新（上表）。
5. 結果が `話した/資料/アポ/訪問済` なら **フォローメール下書き** を作る（§4-3）。`留守/受付/断り/NG/番号違い` は作らない。
6. 解釈不能行は活動CSVに 解釈状態=不能 で残し（原文は捨てない）、朝の1通の「栓」に原文を載せて聞き直す。
7. 元メモ列があるので、部隊の解釈違いを岩崎が後から直せる。直し方は同じ書式で再送（`C000016 訂正 次:10/4`）→ 最新行で上書き。

## 4. 「夜のインサイド」v2 の仕様

順番は「岩崎の入力を先に全部読む → 書く → 送る → 明日を作る」。送るより先にメモを読むのは、メモに `NG` があれば承認済みでも送ってはいけないから。

### 4-1. 岩崎の返信の解釈（承認・修正・却下・会社情報・一言メモ）
- 検索: `from:daikiiwasaki59@gmail.com subject:朝の1通 newer_than:2d`。全スレッドの岩崎の返信を時系列に。
- `承認 A0007 A0008` → approvals.csv 状態=承認。`修正 A0007 <指示>` → 状態=修正、岩崎メモ=指示、下書きを直して新IDで再登録。`却下` → 状態=却下。
- 同じ依頼IDに矛盾する指示（承認と却下）があれば **後の行を採用** し、log に残す。
- 存在しない依頼ID、依頼IDなしの「承認」→ 解釈不能。何も承認しない。
- 一言メモは §3。

### 4-2. 送信（承認済みだけ）
- 対象: approvals.csv 状態=承認 かつ 処理日時が空。上から最大5通（仮置き、`_common.md` §3）。
- 送信前チェック（1つでも落ちたら送らず、状態=保留、理由を岩崎メモに）:
