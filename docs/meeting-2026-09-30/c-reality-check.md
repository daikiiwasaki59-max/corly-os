# C. 現実チェック — 岩崎1人で回るか、どこで破綻するか

作成日: 2026-09-29 / 担当: 会議の「反対側」（実行可能性の検証）
前提: 岩崎 週30〜40時間（実績値: `00_charter.md`）。10/1 譲渡、11月 解散決議→清算。譲渡後の収入は燃料 3〜5万円/月＋手元資金（実績値: `07_strategy.md` §1）。60日目標: 管理会社1社（継続）＋燃料大口2件（実績値: 岩崎承認 2026-09-11）。営業の軸は電話→訪問（今回の前提）。

## 結論（先に10行）
1. **10月第1〜2週に営業へ使える時間は週 8〜10時間（仮置き）。週35時間の 4分の1。** 残りは譲渡・清算・調整・承認・移動で消える。
2. **電話が軸なのに、管理会社204社の電話番号が0件（実績値: `pm-list-osaka-master.csv` 電話列 0/204、メール列 0/204）。** 番号を誰かが埋めない限り Week 1 の営業成果はゼロ。夜の部隊は「メール下書き3件/日」の設計で、電話営業を支援する形になっていない。
3. **燃料の大口2件は、60日計画の期限（11/10）には間に合わない可能性が高い。** 新規接触は「除外リストの確認方法」と「パトロール給油の4点確認」が埋まるまで禁止（実績値: `07_strategy.md` §4-2、`routines/inside-sales-night.md` §6）。今日 9/29 時点でどちらも未登録、接触は0件。残り 42日。
4. **法務チェックリストA（10/1 まで）12項目のうち完了の記録が無い**（実績値: `legal-tax-issues.md` チェックリストA、全項目未チェック）。10/1 は明後日。譲渡後5〜10日で社保・雇用保険の期限が走る（実績値: 同B）。
5. **庄栄興産・LIOAS との条件はメール1本も無い**（実績値: `INPUT_REQUIRED.md` §0-2 未チェック、LIOAS は契約書なし `01_products.md`）。「庄栄興産の岩崎」「LIOAS の岩崎」と電話で名乗る根拠が、今のところ口頭のみ。
6. **50万円/月の組み立ては分配率 r ≥ 1/2 が前提**（仮置き: `07_strategy.md` §2）だが、r の交渉は一度もしていない。前提が外れると必要件数が1.5倍（r=1/3 で 59件/月 vs r=1/2 で 39件/月。仮置き: 同§2）。
7. **大槻の空き稼働が未登録のまま「清掃は今日から売れる」としている。** 30〜50室 × 3〜5時間 ＝ 90〜250時間/月（実績値からの試算）に対し1人の月間稼働は 160〜176時間（仮置き: 8時間 × 20〜22日）。上限側なら既に満杯。外注に振れば粗利 5%（実績値: 明細書）。
8. **承認はメール返信、LINE は未構築。** 岩崎が朝の1通を見ない日が2日続いたら、承認待ちだけ積み上がる設計。上限が無い。
9. **滑走路は「400万円」ではない。** 手取りは退職金・税・清算後の残余分配で決まり、シート上の試算のみ（実績値: `INPUT_REQUIRED.md` §0）。対価の入金日と退職金の支給時期を確認しないと 10〜12月の現金が読めない。
10. **Week 1 は5つに絞る（§3）。** 譲渡の最小書類、庄栄興産への条件メール、電話番号21件、大槻の空き、滑走路の確定。燃料の新規接触・提案書10ページ・リスト拡張・LINE構築は切る。

## 5. 法令・信用の注意（論点整理まで。**最終確認は専門家へ**）

| 論点 | 何が問題になりうるか | 今の対応（案） |
|---|---|---|
| **電話での名乗り** 「庄栄興産の岩崎」「LIOAS の岩崎」 | 雇用でも役員でもない者が社名だけで名乗ると、相手の誤認と名板貸の論点（`legal-tax-issues.md` 論点6）。LIOAS は契約書なし（実績値: `01_products.md`）。庄栄興産側が「岩崎が当社名で電話する」ことを知らなければ、クレームが庄栄興産に入った時点で信用が壊れる | 名乗りは「庄栄興産と業務委託で営業をしている岩崎」のように立場を1語入れる。庄栄興産・LIOAS からの条件メール（§4 #3・#4）の返信を根拠として保存。名刺も同じ表記 |
| **再勧誘の拒否** | B2B は特定商取引法の適用除外が原則（26条1項1号。`legal-tax-issues.md` 論点7）だが、契約目的で判断されるため個人オーナー・自主管理は電話勧誘販売の規制（再勧誘禁止）が及びうる。B2B でも「もう電話しないで」への再架電は信用の問題 | 断られた先は即 連絡NG＝TRUE（憲法の禁止事項）。個人オーナーには電話営業をしない。同一社への架電は月2回まで（仮置き） |
| **通話内容の記録** | 相手の担当者名・個人携帯は個人情報（`legal-tax-issues.md` 論点10）。録音や逐語メモを AI に渡すと目的外利用・提供の論点。録音自体は当事者録音として直ちに違法ではないとされるが、用途の説明が要る | 一言メモは「会社名・要旨・温度感・次アクション」だけ。担当者の個人名・携帯は正データ（スプレッドシート）側に置き、AI には取引先IDと法人情報のみ。録音音声を AI に入れない |
| **清算中の法人名でメール・名刺・見積を出さない** | 清算中の会社は原則、清算目的の範囲でしか活動できない（`legal-tax-issues.md` 論点2）。CORLY 名義の新規契約・請求は避ける | 10/1 に一括で切替: Gmail の署名、名刺の在庫、freee の請求書ひな形、振込先、ドメインのメールアドレス。`00_contact.md` の所在地・電話・メールは **個人事業の連絡先** で登録する |
| **営業メールの表示義務** | 特定電子メール法。送信者名・住所・受信拒否先が無いメールは出せない（`00_contact.md`。実績値: 部隊は未登録なら送らない設計） | 現状の設計を維持。会社基本3行は個人事業の情報で埋める |
| **配送業者6社の既存顧客** | 除外リスト未整備のまま架電すると「知らなかった」では済まない。LIOAS・配送業者との信用が一度で終わる | 確認方法が登録されるまで燃料の新規接触ゼロ（現状の設計を維持） |
| **建設業許可・一括下請負** | 原状回復は1件500万円未満（税込）なら許可不要だが分割契約は不可。庄栄興産が元請で工務店へ丸投げすると一括下請負の論点（`legal-tax-issues.md` 論点9） | 提案書の契約構造（庄栄興産が請負当事者か取次か）を決めるまで、電話では「立会と工事の窓口になれる」までに留め、契約形態を口にしない |
| **カミックスのリスト** | 営業秘密・契約上の守秘（`legal-tax-issues.md` 論点8） | 使わない（会議決定 2026-09-11）。電話帳代わりにも開かない |

## 6. AI部隊への注文 — 「やられると岩崎の時間が増えるだけ」の設計

### 6-1. 今の設計で時間を増やす箇所
| 箇所 | 問題 | 実績値の根拠 |
|---|---|---|
| 夜の部隊が毎日「初回メール下書き 最大3件＋返信下書き」を承認待ちに積む。**積み上がりの上限が無い** | 岩崎が2日見なければ 6〜10件、1週間で 20件超。全部読まないと承認できない | `routines/inside-sales-night.md` §4・§5 |
| 朝の1通が7節構成（承認待ち／期限／予定／昨夜／返信／栓／返信の書き方） | 毎日同じ「栓4件」を読まされると、3日目から開かなくなる | `routines/morning-brief.md` 本文の型。9/30 初回実行で栓4件（`data/log.csv`） |
| 承認をメール返信の文字列解析に頼る。「読み取れない行は無視」 | 岩崎の承認が無視されると翌朝また同じ件が出て、二重に読む | `routines/inside-sales-night.md` §2 |
| 部隊の設計が **メール営業前提**。電話が軸なら「明日の電話先5社＋30秒トーク＋相手固有1行」が欲しいのに、出てくるのはメール下書き | 岩崎が電話前に自分で調べ直す時間が増える | `routines/inside-sales-night.md` §5、`07_strategy.md` §4-1 のチャネル決定との矛盾（§1-3） |
| 月曜は 6:30 朝の1通＋7:00 週次レビューの2通 | 週の頭に読む量が倍 | `routines/TRIGGERS.md` |
| 週次レビューの「今週の一手3つ」に岩崎の所要時間が付いていない | 一手が「リストを50社に」だと岩崎の週末が消える | `routines/exec-weekly.md` §4 |

### 6-2. 部隊が守る上限（仮置き。2週間回して見直す）
| 項目 | 上限 | 根拠（仮置き） |
|---|---|---|
| 岩崎のAI対応時間 | **1日15分以内**（朝の承認5分＋一言メモ5分＋修正5分） | §1 の配分 30分/日の半分に抑え、残りを予備に |
| 新規の承認待ち作成 | **1日3件まで。未処理が5件を超えたら新規作成を停止** | 岩崎が1件1分で読める量。5件超は「見ない」に転ぶ |
| 未処理の承認待ちの保持 | **3日で「保留」に落として一覧から消す**（却下ではない） | 古い下書きは相手の状況も変わる |
| 岩崎の返信が無い日 | **2日続いたら部隊は新規作成を止め、朝の1通を「承認待ち N件のみ」の3行にする** | 見ない日を責めず、積み上げを止める |
| 朝の1通の長さ | **20行以内。承認待ちは上位5件だけ全文、残りは件数のみ。「栓」は初回だけ全文、翌日から1行**（例: 栓4件・変わらず） | 開くコストを下げる |
| 岩崎への質問 | **全部隊合わせて1日1問、週次レビューを含めて週7問** | 質問は岩崎の思考時間を奪う。答えられない質問は `INPUT_REQUIRED.md` に置くだけ |
| メール下書きの長さ | **初回 200字以内・件名20字以内、返信 150字以内** | 岩崎が読んで承認する時間＝文字数 |
| 承認の返信形式 | **「承認 全部」「却下 全部」を受け付ける。1行で済ませられるようにする** | 1件ずつ ID を打たせない |
| 一言メモへの追加質問 | **ゼロ。分からない項目は空欄で記録し、翌朝の1通に1行だけ** | 移動中に往復させない |
| 週次レビューの「一手」 | **3つ合計で岩崎の所要 2時間以内。各案に所要時間を付ける** | 週30〜40時間の中に収まらない一手は提案しない |
| 送信数 | **1回の実行で最大5通**（現行どおり）。加えて **同一社への再送は7日空ける** | `routines/_common.md` §3 |
| 電話が軸の場合の夜の部隊の成果物 | **「明日の電話先5社」（社名・番号・相手固有1行・30秒トーク）を1枚。メール下書きは電話後のフォロー用のみ** | 岩崎の準備時間をゼロにする |

### 6-3. 設計の変更提案（岩崎の判断待ち）
1. **チャネルを決める**: 「電話→訪問」か「紹介・業界団体→メール」か。前者なら夜の部隊の成果物を 6-2 の最終行に変える。後者なら電話番号収集は不要でメールアドレス収集に置き換える。両方は岩崎の時間で回らない。
2. **60日計画の時計を 10/1 に置き直す**: 9/12 起算だと燃料は「接触0で残り42日」。目標を「管理会社1社＋燃料は紹介ルート1件」に下方修正するか、期限を 11/30 に置き直すかを決める。数字を変えずに置くと、週次レビューが毎週「未達」しか言わなくなる。
3. **月曜の2通を1通にまとめる**（週次レビューの結論3行を朝の1通の先頭に入れる）。
